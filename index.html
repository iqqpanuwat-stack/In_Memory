In-Memory คืออะไร

ฐานข้อมูลทั่วไปเก็บข้อมูลบนดิสก์แล้วดึงขึ้นมาอ่านเมื่อต้องใช้ ส่วนแบบ In-Memory จะเก็บข้อมูลชุดที่ใช้งานไว้ใน RAM ตลอดเวลา การอ่านและเขียนจึงไม่ต้องผ่านการหมุนหัวอ่านหรือคิว I/O ของดิสก์

แนวคิดหลัก

ย้ายข้อมูลที่ถูกเรียกบ่อยมาไว้ใกล้ CPU ที่สุด เพื่อลดเวลารอ

ตัวอย่างเครื่องมือ

Redis, Memcached, Hazelcast, Apache Ignite, SAP HANA และ SQLite แบบ :memory:

ตัวอย่างในชีวิตจริง

หน้าสินค้าขายดีของร้านออนไลน์ที่มีคนเปิดพร้อมกันหลายพันคน ดึงจาก Cache แทนการถามฐานข้อมูลทุกครั้ง

หลักการสำคัญ

ทำงานอย่างไรเบื้องหลัง

ระบบ In-Memory ส่วนใหญ่ยึดหลักร่วมกัน 4 ข้อ

โครงสร้างแบบ Key–Value

เข้าถึงข้อมูลด้วยคีย์ผ่าน Hash Table ใช้เวลาคงที่ O(1) เช่น user:42 ได้ข้อมูลผู้ใช้ทันที

TTL และการหมดอายุ

ตั้งอายุข้อมูล เช่น 60 วินาที เมื่อครบกำหนดระบบลบเองเพื่อให้ข้อมูลไม่เก่าเกินไป

Eviction Policy

เมื่อ RAM เต็ม ต้องเลือกข้อมูลที่จะทิ้ง เช่น LRU (ไม่ได้ใช้นานที่สุด) หรือ LFU (ใช้น้อยที่สุด)

Persistence แบบเลือกได้

RAM ข้อมูลหายเมื่อไฟดับ จึงมีตัวเลือกทำ Snapshot เป็นช่วง ๆ หรือบันทึก Log ทุกคำสั่ง (AOF) ลงดิสก์

จำลอง Cache-Aside

ทำไมถึงเร็วและน่าใช้

เร็วมาก

ตอบสนองระดับไมโครวินาที รองรับหลายแสนคำขอต่อวินาทีบนเครื่องเดียว

ลดภาระฐานข้อมูลหลัก

คำขออ่านซ้ำ ๆ ถูกตอบจาก Memory จึงช่วยให้ฐานข้อมูลไม่ล่ม

โครงสร้างข้อมูลหลากหลาย

Redis มี String, List, Set, Sorted Set, Hash เหมาะกับงานอันดับคะแนนและคิว

ขยายแบบกระจายได้

แบ่งข้อมูลเป็น Shard และทำ Replica เพื่อรองรับผู้ใช้จำนวนมาก

ข้อจำกัด

สิ่งที่ต้องระวัง

In-Memory ไม่ใช่คำตอบของทุกงาน ควรรู้ข้อจำกัดก่อนเลือกใช้

ข้อจำกัดผลกระทบแนวทางรับมือ
RAM ราคาสูงต่อ GBเก็บข้อมูลทั้งหมดได้ไม่คุ้มเก็บเฉพาะข้อมูลที่ถูกใช้บ่อย
ข้อมูลหายเมื่อรีสตาร์ตเสี่ยงสูญเสียข้อมูลล่าสุดเปิด Snapshot/AOF และทำ Replica
ข้อมูลไม่ตรงกับฐานข้อมูลหลักผู้ใช้เห็นข้อมูลเก่า (Stale Data)ตั้ง TTL สั้น และลบ Cache เมื่อมีการแก้ไข
ความจุจำกัดตามเครื่องRAM เต็มแล้วข้อมูลถูกทิ้งกำหนด Eviction Policy และทำ Sharding
การนำไปใช้

ใช้ที่ไหนได้บ้าง

Session ผู้ใช้

เก็บสถานะการล็อกอินเพื่อให้ตรวจสอบได้ทันทีในทุกคำขอ

Leaderboard เกม

ใช้ Sorted Set จัดอันดับคะแนนแบบเรียลไทม์

Rate Limiting

นับจำนวนคำขอต่อ IP ต่อนาทีเพื่อป้องกันการเรียกใช้ถี่เกินไป

วิเคราะห์ข้อมูลเรียลไทม์

ตรวจจับธุรกรรมผิดปกติของธนาคารได้ทันก่อนอนุมัติ

สรุป

In-Memory แลกค่าใช้จ่ายของ RAM กับความเร็วที่สูงขึ้นหลายเท่า เหมาะกับข้อมูลที่อ่านบ่อยและต้องการความไว แต่ควรออกแบบเรื่อง TTL, Eviction และ Persistence ให้เหมาะกับงาน และใช้ควบคู่กับฐานข้อมูลหลักเสมอ
